# Scouting next-match progression

Submitting a match report previously left the scout on the completed match until its shared submission window elapsed. The worker also rejected the next match because it only accepted the shared live match.

In TBA mode, `/event-context?assign=true` selects that scout's first unsubmitted, unexpired form among the shared current match and its immediate successor. Submission validation and the check after drawing uploads use the same selection. A successful report immediately loads the next assignment and an empty draft; the previous match's countdown does not apply to it. After submitting that following report, the scout stays there until the shared current match advances, preventing repeated submissions from running through future matches. Scheduled or actual start times do not gate submissions. Other scouts can finish their current match until its own deadline, and Admin's Competition overview keeps the shared current match. Manual scheduling stays under the lead's control.

The frontend starts a fresh context request after submission and ignores older responses, including a poll started before the report was saved. A successful save stays successful when the next-assignment refresh fails; the completed draft stays disabled until a later refresh. Schedule failures and temporarily empty schedules return 503 for assignment requests rather than a false empty assignment. The page keeps its last valid match, notes, counters and drawings, allows continued editing, pauses submission while it cannot verify the schedule, shows a retry banner, and resumes automatically after recovery. Known deadlines still expire normally. Admin can still load configuration during an outage. Expired, duplicate, skipped and wrong-team submissions remain rejected. Existing reports, settings and API keys are unchanged, with no database migration.

Validation on 16 October 2026:

- A regression test reproduced the old behavior: after saving match 1 before its cutoff, the next context incorrectly stayed on match 1. It now opens and accepts match 2 while unfinished scouts and the Admin overview remain on match 1.
- All 83 Scouting worker tests and populated migration checks pass, including capped progression, acceptance despite future scheduled start times, recovery from failed or empty schedules, expired forms and expiry during drawing uploads. Frontend/worker type checks, production build, Worker dry run, tenancy lint and text-field lint pass.
- Chrome at 320, 390 and 768 pixels in both themes saves two consecutive reports with the correct match/team snapshots, clears answers and drawings between matches, keeps the next draft editable after the previous deadline, and ignores a delayed pre-submit poll. Failed post-submit refreshes retain the successful save and recover on refresh. No browser exceptions or horizontal overflow.
- At the same widths and themes, 503 and network failures preserve notes, counters, drawings and the assigned team, allow editing, prevent unverified submissions, and recover without resetting the draft. A real match/team change still clears the entire draft.
